网站或 App 打不开：从影响范围开始定位网络问题

网络问题最省时间的判断方式，不是先改 DNS 或重置网络，而是先看“影响了多少东西”。影响范围一旦确定，后面的检查会短很多。

第一步：先看影响范围

现在的表现先往哪里查
所有网站、App 都没网络设备网络、路由器、系统代理、VPN 状态
只有一个网站或平台异常平台状态、账号、浏览器/App、当前网络出口
浏览器正常，只有 App 不行App 权限、后台网络、版本、缓存
App 正常，只有浏览器不行扩展、Cookie、缓存、浏览器代理或安全过滤
换 Wi‑Fi / 热点立刻恢复原网络的 DNS、路由、过滤或代理

所有网站和 App 都不能联网

先确认设备真的连上了 Wi‑Fi 或移动网络，再用另一台设备测试同一网络。只有一台设备没网，优先看这台设备；多台设备同时异常，更像路由器、宽带或当前网络本身的问题。

如果故障出现在使用 VPN、代理或网络工具之后，先退出相关工具，再检查系统里有没有残留的手动代理。不要一开始就做“网络重置”，它会清掉 Wi‑Fi、代理和 VPN 等配置。

只有一个网站或平台打不开

先打开两三个无关网站做对照。如果其他站都正常，就不要把整台设备当成“断网”。这时更值得看平台状态、登录状态、浏览器/App 本身，以及当前网络出口是否只影响这个服务。

例如 ChatGPT 能打开但登录循环、Netflix 只缺一部影片、Telegram 只是收不到登录码，都不属于“所有网络都坏了”。这些问题应该进入对应平台页面继续查。

浏览器和 App 表现不一样

浏览器正常，App 不行

检查 App 的移动数据/后台网络权限、版本和缓存；换网络后再试一次。

App 正常，浏览器不行

用无痕窗口测试，再暂时停用扩展，检查 Cookie、缓存和浏览器自己的代理设置。

只有一台设备异常

不要先动路由器。把重点放在这台设备的网络设置、代理和安全软件。

换网络后立刻恢复，说明什么

同一台设备、同一个 App，只换 Wi‑Fi / 移动网络就恢复，说明账号和设备本身大概率没有完全失效。下一步应查原网络的 DNS、路由、过滤、代理或出口，而不是继续重装 App。

如果主要表现是“域名打不开、换网络就恢复”，继续看 DNS 异常怎么判断。

什么时候检查 DNS

DNS 更适合解释“域名解析失败、浏览器提示找不到服务器、换网络后恢复”这类症状。整台设备完全没网、VPN 刚连接就断流时，不要把 DNS 当成第一步。

什么时候可以停止继续改设置

如果问题只发生在一个平台，而且该平台的官方状态页正在报告故障，继续清缓存、重置路由器或改 DNS 往往不会带来收益。此时保留当前可用配置，等服务恢复更合理。

网络重置为什么放最后

Windows、Android、iOS 和 macOS 都有不同形式的网络重置，它可能同时清掉 Wi‑Fi、代理、VPN 或其他网络配置。只有在基础网络确实异常、重启和常规检查都无效时再使用。
